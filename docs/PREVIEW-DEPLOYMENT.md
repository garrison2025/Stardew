# Preview deployment
CI exports separate public-preview-build and private-workspace-preview-build artifacts after tests pass. Use distinct Cloudflare Pages projects (not paths under the same origin), both static files, no paid database or API. Build commands: npm run build (output dist) and npm run build:workspace (output dist-workspace); Node 22. In public project set PUBLIC_WORKSPACE_ORIGIN to the actual HTTPS private project origin only after deployment. Do not publish unreviewed official assets. Verify public and private root, all 16 routes, 404, response headers, robots, no third-party requests, storage isolation, and no ads. Both previews remain noindex. Production domain, legal clearance and independent actual-game fixtures are still missing; do not flip release flags. CI artifact is not a live deployed website.

## Transfer and live acceptance
CI checks total compressed JS/CSS, maximum compressed HTML, and bundled PNG sizes. These are transfer-size budgets, not measured Core Web Vitals. After deploying two distinct HTTPS preview origins, run `npm run audit:live -- https://PUBLIC_ORIGIN https://PRIVATE_ORIGIN` from the repository. It checks all 16 paths, noindex header, CSP, robots, PNG MIME and signature, artwork credits, 404 and private save input separation. No live URL or deployment is assumed. The private reference now offers exact integer screenshot dimension candidates and an editable terrain JSON export, but does not detect game tiles. Production release gates remain closed.

## Actual public preview
Owner-provided deployment: https://stardew-67b.pages.dev/ . Public tracker requires a separately deployed private workspace URL; never point both builds at the same origin. Set PUBLIC_SITE_ORIGIN to the actual public HTTPS origin and PUBLIC_WORKSPACE_ORIGIN to the distinct private HTTPS origin. The public build now emits a build-revision meta tag when Cloudflare or GitHub provides a valid commit SHA, so deployed HTML can be compared with the intended commit. No production indexing or ads were enabled.

## Public-only live acceptance
The public preview can be audited independently before the private deployment exists: `npm run audit:live -- https://stardew-67b.pages.dev`. Add the private HTTPS origin when available and `--revision FULL_SHA` to require a particular deployed commit. The audit validates consistent revision metadata across every tool, CSP network isolation, noindex, assets, 404 and save-input separation; the dual-origin check also requires the public tracker link to the private tracker. The dedicated Live public preview acceptance workflow runs the public audit when its code changes and supports manual execution. A public-only pass does not imply private deployment or production release approval.

## Guarded production output
After all approval evidence is recorded and the real apex / app origins are configured, `npm run build:production` can generate a separate `dist-production` output. The default `npm run build` and workspace build remain preview/noindex. The command currently refuses to run. The Cloudflare Pages project must serve the approved custom domain and redirect the pages.dev mirror and www correctly; do not use the guarded output on an unapproved host. No ads are included. Run full live acceptance on the actual domains before advertising.

## Revision-pinned main deployment evidence
Every main push now triggers the read-only Live preview verification workflow. It polls the two configured Pages roots for the exact main commit revision, then runs the existing full route/headers/assets/404/save separation audit against both origins with that same expected SHA. Older or mixed deployments cannot pass. The bounded poll fails if either site does not catch up; overlapping main pushes cancel obsolete checks. PR checks still inspect the deployed preview pair, not the proposed commit; manual runs require an explicit revision. No write access to Cloudflare or production approval is implied. These are preview gates only; noindex and ads-off remain unchanged.
