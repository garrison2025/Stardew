# Concurrent manual edits
Per-editor IndexedDB compare-and-swap for standard and remixed bundles, museum, walnuts, four collection pages, rule calculators using useSaved, manual goals and standalone indoor layouts. Each editor captures its own exact JSON baseline and active farm when loaded. The read and comparison/write occur in one read-write transaction; a change from another tab, save merge, backup restore or clear rejects stale writes and preserves unsaved UI state for export. Identical stored content does not conflict. No shared read-cache baseline, no schema migration, no new keys or dependency. Existing scene-book revision guard and atomic restore/merge remain unchanged. This is conservative conflict rejection, not automatic conflict merging or BroadcastChannel live synchronization. Browser regression uses two tabs and verifies the winner survives reload; further auditing is required for other direct writeLocal consumers.
Candidate: successful commits emit scoped, content-free BroadcastChannel signals; read-only summaries refresh and a notice appears, but editing forms retain unsaved values. Existing compare-and-swap remains. No automatic conflict merge.
