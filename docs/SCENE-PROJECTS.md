# Local project library and portable layout codes
Private workspace migrates the legacy active scene on first save without deleting it. Up to 10 named projects and five distinct saved checkpoints per project (latest plus four older), optional session-only 1.2s debounced autosave waits until gestures end. Switching saves active plan first; restore is editable and undoable; deletion requires confirmation and cannot delete active project. Atomic IndexedDB transaction checks expected revision and updates both library and legacy crop-tool scene key; conflicting tabs report error and disable autosave. No cloud sync. Wait for saved status before closing; last in-flight/debounced edits can be lost. Screenshots, raw game XML, weather, selections and camera are not stored. Existing workspace backup includes library; complete backup restore remains pending.
Share codes are bounded, base64url JSON, built-in original maps only (300 objects, 8,000 characters); contain map ID, season, item types, coordinates and rotations, no project name, save XML, private terrain, original object IDs or screenshot. Public link uses fragment (not HTTP query); recipient must preview and explicitly open. Private workspace generates code only, which can be pasted in public tool; no automatic transfer between origins. Share is not encrypted, no revocation; anyone holding code may view it. Large layouts use JSON export. No backend or new dependencies. Release gates and SEO unchanged. Synthetic tests, not commercial release or official game map approval.
