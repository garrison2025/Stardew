## Release evidence procedure
1. Verify full CI on the exact candidate commit. Save run URL, public and workspace build artifacts, dependency lock and browser evidence.
2. Record the actual deployment revision for both separate origins. Use the read-only Live preview verification workflow with the full expected SHA and both origins. Public-only is explicitly incomplete.
3. Review the Chromium lab performance JSON (desktop and throttled mobile; no physical-device or field CWV claim). Record physical iOS Safari and Android Chrome checks: farm canvas/touch, scroll, tool inputs, local save import, export, no external requests. No real personal save uploaded.
4. Rehearse rollback on the preview pair only, with the owner-approved prior successful deployment IDs. Record candidate SHA, prior SHA, deployment IDs, time, post-rollback read-only audit and restored candidate audit. Never treat a local build as a Cloudflare rollback. Do not modify production domains during a rehearsal.
5. Record US SERP sampling date, actual query, device/country, competing page intent, decision and matching route; original Semrush export and private keyword evidence stay out of the public build.
6. Review factual data and each material source's usage terms and retain evidence; original practice graphics are not official assets. Obtain independent game-save and in-game output fixtures (version and expected values).
7. Only after documented approvals for rights, data, fixtures, SERP and each route, bind approved apex and app subdomain and run the gated production build. Never flip approvals just to deploy. Keep private workspace noindex, ads disabled until a separate approved review.
The public and workspace preview modes remain noindex; no production deployment, rights approval, private live-origin verification, physical device testing or rollback rehearsal is asserted by this document.
